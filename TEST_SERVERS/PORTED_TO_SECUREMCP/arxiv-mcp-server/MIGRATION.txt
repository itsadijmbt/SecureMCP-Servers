MIGRATION: arxiv-mcp-server, low-level MCP Server -> SecureMCP
Upstream base: blazickjp/arxiv-mcp-server @ 2116bf3 (2026-04-25, v0.4.12-6)

WHAT
- src/arxiv_mcp_server/server.py and __init__.py only.
- Upstream is not a FastMCP server. It uses the low-level Server class: one
  list_tools() that returns 10 Tool objects and one call_tool() that branches
  on the tool name. SecureMCP has no such pair, so each of the 10 tools is a
  typed @app.tool() function that builds the same arguments dict and awaits the
  same, untouched handle_*() function in tools/.
- The 10 tools were checked against upstream's 10 inputSchema objects: names,
  required flags and defaults match.
- An error payload from a handler still raises (helper _tool_error_message).
- The original code is kept as comment blocks in server.py.

CORRECTED IN THIS REVISION (2026-10-12)
- 3 tool parameters given a plain type: search_papers.max_results (int),
  search_papers.categories (list), watch_topic.categories (list). They were
  published as "string". Old type kept in "# was:".

BROKEN ON PURPOSE
- The 4 prompts (list_prompts / get_prompt) are not served. Putting them back
  means writing 4 new prompt functions and turning upstream's message objects
  into text; that is new code, not a swap. The prompt files are untouched.
- The streamable-HTTP transport and its DNS rebinding protection.
- Results are returned as plain text, not as MCP TextContent objects.
