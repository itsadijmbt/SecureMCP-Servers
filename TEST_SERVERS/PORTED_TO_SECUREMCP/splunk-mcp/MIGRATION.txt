splunk-mcp: FastMCP -> SecureMCP migration
==========================================

CHANGES WE MADE
---------------

splunk_mcp.py -- the only edited file.

  1. Import swap.
       was:  from mcp.server.fastmcp import FastMCP
       new:  from macaw_adapters.mcp import SecureMCP
     The HTTP/SSE imports (fastapi, uvicorn, starlette, mcp.server.sse)
     are commented out -- they were needed only for the dropped HTTP
     layer (see Change 3).

  2. Constructor swap.
       was:  mcp = FastMCP("splunk", description=..., version=...,
                            host="0.0.0.0", port=FASTMCP_PORT)
       new:  mcp = SecureMCP("splunk")
     SecureMCP only accepts `name` (skill Step 1b). The dropped kwargs
     (description, version, host, port) are FastMCP-only.

  3. HTTP/SSE transport + OpenAPI documentation surface dropped.
       Original served 5 HTTP routes on top of FastMCP:
         /sse              SSE transport for MCP protocol clients
         /messages         SSE message posting
         /docs             Swagger UI
         /redoc            ReDoc UI
         /openapi.json     OpenAPI 3.0 schema export
       Under SecureMCP the mesh carries traffic and the MACAW Console
       provides discovery UI. All 5 routes commented out as one block
       with a PORT NOTE explaining the rationale.
       Also dropped:
         - FastAPI `app` instance (host for the routes above)
         - SseServerTransport (the SSE backend)
         - uvicorn (the HTTP server)
         - `mcp._mcp_server.run(...)` reach-in inside the /sse handler
           (Hard Rule 3 forbids that under SecureMCP; line is dead
           because the SSE branch is gone)

  4. Redundant `list_tools()` tool dropped.
       The original had `@mcp.tool() async def list_tools()` that
       introspected `mcp._tools` and returned the list. SecureMCP +
       MACAW provides this mesh-natively at MACAWClient.list_tools()
       (macaw_adapters/mcp/client.py:280). The manual tool was a
       reinvention of what the mesh now does for free, so it is
       dropped. Original body preserved as a comment block.

  5. Entry-point rewrite.
       The original __main__ branched on `argv[1]`:
         - "stdio" -> mcp.run(transport="stdio")
         - "sse"   -> uvicorn.run(app, host="0.0.0.0", port=FASTMCP_PORT)
       Both branches collapsed into a single sync mcp.run() call. The
       MACAW mesh is the only transport under SecureMCP, so the
       argv-based selector is no longer meaningful. Original block
       preserved as a comment.

  6. The 11 remaining @mcp.tool() functions are UNCHANGED.
       search_splunk, list_indexes, get_index_info,
       list_saved_searches, current_user, list_users,
       list_kvstore_collections, health_check,
       get_indexes_and_sourcetypes, health, ping.
     Bodies, signatures, and Splunk SDK calls are byte-for-byte the
     same as the original (Hard Rule 9). Splunk auth env vars
     (SPLUNK_HOST, SPLUNK_PORT, SPLUNK_TOKEN, SPLUNK_USERNAME,
     SPLUNK_PASSWORD, VERIFY_SSL) and get_splunk_connection() helper
     are unchanged.


WHY THIS PORTS WITHOUT BUSINESS LOGIC LOSS
------------------------------------------

The 11 tool functions are pure Splunk SDK code. They don't touch the
MCP framework -- they call `splunklib.client.connect(...)` and return
JSON-serializable dicts. The framework swap (FastMCP -> SecureMCP) is
entirely at the entry/transport layer, not the tool layer.

The HTTP/SSE/docs surface that was dropped was used by non-MACAW
consumers (Claude Desktop SSE clients, API gateways, OpenAPI catalogs).
For a deployment where every caller is MACAW-native, the mesh provides
the equivalent functionality:

  Original HTTP feature   ->  MACAW equivalent
  GET /openapi.json       ->  MACAWClient.list_tools(server_name="splunk")
  GET /docs (Swagger UI)  ->  MACAW Console activity graph
  POST /messages, /sse    ->  MACAWClient.invoke_tool(name, params, ...)

No script or additional tool was added -- the mesh handles discovery
automatically when SecureMCP registers at startup.


VERIFICATION
------------

Boot the server (Terminal 1):

    cd ~/MACAW-MCP-STORE/TEST_SERVERS/PORTED_TO_SECUREMCP/splunk-mcp
    pip install -e .            # or pip install -r requirements (deps stay)
    export SPLUNK_HOST=<host>
    export SPLUNK_USERNAME=<user>
    export SPLUNK_PASSWORD=<pw>
    python splunk_mcp.py

Expected log:
    Starting Splunk MCP server on the MACAW mesh
    SecureMCP server 'splunk' started
    Registered as agent: local:<user>/app:securemcp-splunk:<hash>

Mesh smoke test (Terminal 2):

    python client-test-macaw.py splunk <client_name>

The 3-test suite (see client-test-macaw.py header):
    TEST 1: list_tools         - 11 tools advertised
    TEST 2: ping               - handler reachable (no Splunk needed)
    TEST 3: health_check       - exercises Splunk lazy connect


KNOWN GAPS
----------

  - HTTP/SSE consumers cannot reach this server. If any non-MACAW
    consumer existed (Claude Desktop SSE client, BI catalog hitting
    /openapi.json, API gateway), it must switch to a MACAWClient.
    This was confirmed acceptable for this deployment because all
    current callers are MACAW-native.
  - The original `mode=sse` and `mode=stdio` CLI arguments are
    inert. argv[1] is no longer read.
